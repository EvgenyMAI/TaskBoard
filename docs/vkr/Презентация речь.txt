ТЕКСТ ВЫСТУПЛЕНИЯ К ЗАЩИТЕ ВКР
Ориентир при устном рассказе: около 7 минут. Слайды 9–13 — с паузой на экран.

СЛАЙД 1. Титульный
Здравствуйте, уважаемые члены комиссии. Меня зовут Кострюков Евгений Сергеевич.
Тема работы — микросервисное веб-приложение для управления задачами, проектами и коммуникацией команды.
Научный руководитель — Кузнецова Светлана Валентиновна.

СЛАЙД 2. Постановка, актуальность, цель
TaskBoard объединяет проекты, задачи, обсуждения и отчёты в одном окне.
Актуальность — разрозненные чаты и таблицы, потеря истории и не всем подходит чужое облако.
Цель — работоспособный прототип с проектами, задачами, файлами, уведомлениями и отчётом за период.

СЛАЙД 3. Задачи работы
Пять задач: требования и декомпозиция на сервисы, модели данных и REST, backend, веб-клиент, развёртывание и автотесты с CI.

СЛАЙД 4. Сравнение с аналогами
Сравнение с Jira, Trello и Битрикс24 — в таблице на слайде.
TaskBoard — не их замена, а свой прототип на своём сервере.

СЛАЙД 5. TaskBoard — плюсы, минусы, для кого
Плюсы — свои данные, единый интерфейс, роли и доработка под себя.
Минусы — установка, меньше функций, чем у крупных продуктов, учебный MVP без мобильного приложения.
Подходит малым командам и организациям со своим сервером.

СЛАЙД 6. Требования к системе
Функционально — роли, проекты и задачи, комментарии, вложения, уведомления и отчёты; исполнитель только из участников проекта.
Технически — Docker Compose, JWT, журналы и автотесты в CI.

СЛАЙД 7. Критерии приёмки
Восемь критериев: учётная запись и JWT; проекты, задачи, вложения и чужие уведомления; отчёт, CSV, стенд и CI.
Проверка — тестами и тем, что покажу в интерфейсе.

СЛАЙД 8. Демонстрация интерфейса
Перехожу к работающему прототипу в браузере.

СЛАЙД 9. Главная страница
После входа — главная: навигация к проектам, задачам и уведомлениям, быстрые переходы по разделам.

СЛАЙД 10. Проекты
Раздел проектов: карточки проектов, состав участников и задачи внутри проекта.
При назначении исполнителя доступны только участники этого проекта.

СЛАЙД 11. Карточка задачи
Карточка задачи: статус, описание, комментарии, вложения с предпросмотром и журнал изменений полей.

СЛАЙД 12. Уведомления
Уведомления о событиях по задачам: лента, фильтр непрочитанных, счётчик в шапке.

СЛАЙД 13. Аналитика
Аналитика за выбранный период: сводные показатели, разбивка по статусам и выгрузка отчёта в CSV.

СЛАЙД 14. Архитектура решения
Три уровня: клиент React, три сервиса Spring Boot, у каждого своя PostgreSQL; вложения — в MinIO.
Auth выдаёт JWT; tasks ведёт проекты и задачи; analytics — уведомления и отчёты, данные задач запрашивает по REST.
JWT в tasks и analytics проверяется общей библиотекой taskboard-common.

СЛАЙД 15. Стек технологий
Серверная часть — Java 17 и Spring Boot 3.
Клиент — React 18 и Vite.
Данные — PostgreSQL 16, по отдельной базе на сервис, файлы — MinIO. 
Запуск — Docker Compose,
Качество проверяют Vitest, Playwright и GitHub Actions.

СЛАЙД 16. Схема данных — учётные записи
Модели данных разнесены по трём базам.
Первая схема — база сервиса аутентификации. Таблица пользователей связана с ролями связью многие-ко-многим через промежуточную таблицу. Пароль хранится как хеш.

СЛАЙД 17. Схема данных — проекты и задачи
Вторая база — проект, участники с составным ключом, задачи, комментарии, история; файлы — в MinIO.

СЛАЙД 18. Схема данных — уведомления и отчёты
Третья база — уведомления; отчёты считаются по данным сервиса задач, отдельных таблиц отчётов нет.

СЛАЙД 19. Тестирование
Тестировались серверная часть и логика клиента — Vitest; сквозные сценарии в браузере — Playwright, от входа до отчёта. 
При изменении кода в репозитории запускается прогон в GitHub Actions.
Основные сценарии проходят, весь стенд поднимается через Docker Compose.

СЛАЙД 20. Результаты
Цель достигнута: прототип TaskBoard, пять задач и восемь критериев приёмки выполнены.

СЛАЙД 21. Источники
Использованы источники по микросервисам, Spring Boot, React, PostgreSQL, Docker и JWT — на слайде.
